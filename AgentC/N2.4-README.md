# N2.4 - Complete Markdown Archive & RAG Update Workflow

## Overview

Automated workflow that performs a **complete** markdown archive and RAG update across the entire AgentX codebase (not just `/mnt/datalake/RAG`).

**Workflow ID:** N2.4
**Status:** Ready for deployment
**Priority:** 2

---

## What It Does

This workflow executes three main steps:

### Step 1: Archive All Markdown Files
- Runs `scripts/archive-md-files.sh`
- Archives **all** `.md` files from AgentX codebase
- Preserves folder hierarchy in tar.gz format
- Creates manifest listing all archived files
- Stores in `/mnt/datalake/backups/md-archives/`

### Step 2: Update RAG Store
- Runs `scripts/update-rag-from-md.js`
- Ingests **all** markdown files into RAG system
- Uses SHA256 for deduplication
- Auto-tags based on directory structure
- Source: `agentx-complete`

### Step 3: Store Manifest
- POSTs manifest to `/api/rag/manifests`
- Enables deletion detection for orphaned documents
- Tracks bulk update metadata

---

## Triggers

### 1. Scheduled (Cron)
- **Schedule:** Weekly on Monday at 2 AM
- **Expression:** `0 2 * * 1`
- Ensures RAG stays synchronized with codebase

### 2. Manual (Webhook)
- **Endpoint:** `POST /webhook/sbqc-n2-4-complete-rag`
- **Webhook ID:** `sbqc-n24-complete-rag`
- Use for ad-hoc updates after major documentation changes

---

## Workflow Flow

```
Webhook/Schedule
    ↓
Initialize → Archive → Check Success
                          ↓
                      RAG Update → Prepare Manifest → Store Manifest
                          ↓               ↓
                      Summary ← ───────────┘
                          ↓
                      Log to DataAPI → Respond
```

**Error Handling:**
- Archive failure → Skip RAG update, log error, respond with 500
- RAG failure → Continue to summary with partial status
- Manifest failure → Continue to summary, mark as not stored

## Comparison with N2.3

| Feature | N2.3 (Existing) | N2.4 (New) |
|---------|-----------------|------------|
| **Scope** | `/mnt/datalake/RAG` only | Entire AgentX codebase |
| **Files** | Modified in last 7 days | All markdown files |
| **Limit** | 100 files per pattern | No limit |
| **Size** | First 50KB per file | Full file content |
| **Archive** | No | Yes (tar.gz) |
| **Source** | `nas-docs` | `agentx-complete` |
| **Manifest** | No | Yes |
| **Schedule** | Weekly Sun 3 AM | Weekly Mon 2 AM |

**Use Both:**
- **N2.3:** For external NAS documents (`/mnt/datalake/RAG`)
- **N2.4:** For internal AgentX documentation

## Deployment Steps

### 1. Import Workflow to n8n

```bash
# Copy workflow file to n8n import location
cp AgentC/N2.4-complete-md-rag-update.json /path/to/n8n/imports/

# Or import via n8n UI:
# Workflows → Import from File → Select N2.4-complete-md-rag-update.json
```

### 2. Configure Credentials

1. Go to **Credentials** in n8n
2. Verify **Header Auth account** exists
3. Ensure it has:
   - Name: `x-api-key`
   - Value: Your AgentX API key

### 3. Set Environment Variables

```bash
# In n8n's .env file or environment
BACKUP_DIR=/mnt/datalake/backups
AGENTX_BASE_URL=http://192.168.2.33:3080
AGENTX_API_KEY=your-secure-api-key
```

### 4. Activate Workflow

1. Open workflow in n8n
2. Click **Active** toggle
3. Test with manual webhook trigger

## Troubleshooting

### Archive Script Fails

**Symptom:** Archive status is "error"

**Possible Causes:**
- Insufficient disk space in `/mnt/datalake/backups`
- Permission issues on backup directory
- tar command not available

**Fix:**
```bash
# Check disk space
df -h /mnt/datalake

# Check permissions
ls -ld /mnt/datalake/backups/md-archives

# Create directory if missing
mkdir -p /mnt/datalake/backups/md-archives
chmod 755 /mnt/datalake/backups/md-archives
```

### RAG Update Fails

**Symptom:** RAG status is "error" or high failure count

**Possible Causes:**
- AgentX server not running
- Qdrant/vector store unavailable
- API key invalid
- Network connectivity issues

**Fix:**
```bash
# Check AgentX health
curl http://localhost:3080/health

# Check Qdrant health
curl http://localhost:6333/healthz

# Verify API key
echo $AGENTX_API_KEY

# Check RAG endpoint manually
curl -X POST http://localhost:3080/api/rag/ingest \
  -H "x-api-key: $AGENTX_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"source":"test","path":"test.md","title":"Test","text":"Content"}'
```

### Manifest Storage Fails

**Symptom:** manifest.stored is false

**Possible Causes:**
- n8nAuth middleware blocking request
- Invalid manifest format
- MongoDB connection issue

**Fix:**
```bash
# Test manifest endpoint
curl -X POST http://localhost:3080/api/rag/manifests \
  -H "x-api-key: $AGENTX_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "source": "test",
    "root": "/test",
    "files": []
  }'

# Check MongoDB connection
curl http://localhost:3080/health/detailed | jq '.mongodb'
```

## Maintenance

### Manual Archive Cleanup

```bash
# Keep only last 5 archives
cd /mnt/datalake/backups/md-archives
ls -t agentx-markdown-*.tar.gz | tail -n +6 | xargs rm -f
ls -t agentx-markdown-*.manifest.txt | tail -n +6 | xargs rm -f
```

### Force RAG Re-ingestion

```bash
# Delete all documents from a source
curl -X GET "http://localhost:3080/api/rag/documents?source=agentx-complete" | \
  jq -r '.data[].documentId' | \
  xargs -I{} curl -X DELETE "http://localhost:3080/api/rag/documents/{}"

# Re-run RAG update
node scripts/update-rag-from-md.js --source=agentx-complete
```
