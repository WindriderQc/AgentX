# Curated photo requests in Nestor Famille

Conversational lookup is **off by default** and does not inherit the idle frame's directory, album, or mixed selection. Only the instance operator can explicitly designate a suitable curated Immich album in the existing instance-owned frame config, by setting a separate `conversationLookup` object with `enabled: true` and its own `albumId` UUID. Only photos intended for the shared Family display should be members of that album. No default album is proposed. Each load is revalidated against the current grant and current album membership. Disabling the grant or no longer authorizing that asset denies the next load; an asset still explicitly authorized in a newly designated album may remain available. An already rendered copy cannot be hidden retroactively by that check. The frame's existing operation stays independent.

A pinned device is a Family display scope within the existing LAN application's own access boundary. It is not proof of the owner's identity or owner approval of the device, and this feature is not a general photo permission for all LAN callers. An explicit operator album grant, a verified locked browser pin, a current active Family conversation, and asset eligibility are all required. The browser receives only a short-lived opaque display receipt, tied to the issuing pin and conversation. No provider credentials, raw asset ID, folder path, photo metadata, or Web search are sent with that receipt. Valid receipts can be retried by the issuing browser during their two-minute lifetime. Old cards do not mint fresh receipts; ask again if the picture has expired or otherwise becomes unavailable.

Before enabling: verify the bound album's sharing policy and membership, the configured private processing library ID, Immich's direct asset metadata (canonical UUIDs, timeline visibility, explicit active flags, review tags) and metadata search album filters; run a successful search and image load with a harmless approved fixture and verify a second browser cannot load it. Do not activate with missing, ambiguous or untrusted metadata. The module rejects the canonical review-pending tag, assets outside the album and assets from the ingest library both at lookup and again before serving bytes.
